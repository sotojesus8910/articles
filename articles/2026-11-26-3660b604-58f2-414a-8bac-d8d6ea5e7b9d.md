# 节点表单在提交前做集中校验并聚焦首个错误

## 问题场景

节点录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  cpu: (v) => (/^\d+$/.test(v) ? '' : '节点必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

从长期维护角度看，先把最小可复现的用例固定下来，让容量规划更有依据。

遇到复杂链路时，先把最小可复现的用例固定下来，降低同类问题再次发生的概率。

如果数据量继续增长，需要评估对现有调用方的影响面，减少不必要的返工成本。

从成本角度看，应当拆分步骤以便中途校验，避免资源被长期占用。

在实际落地时，建议先在小流量环境验证行为是否符合预期，确认指标平稳后再逐步放开。

遇到复杂链路时，先把最小可复现的用例固定下来，防止出现隐性回归。

对稳定性要求高的场景，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

在资源受限的环境下，要避免在高峰期执行这类操作，使整体改动风险可控。
