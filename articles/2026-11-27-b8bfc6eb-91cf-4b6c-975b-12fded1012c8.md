# 消息模板动画改用合成层属性避免重排

<!-- content-workspace-job:b8bfc6eb-91cf-4b6c-975b-12fded1012c8 -->

## 问题场景

消息模板抽屉用 left 做滑入动画，低端机上明显卡顿，滚动时更严重。

## 实现步骤

把位移改为 translate3d，动画结束位置由 transform 决定。

```css
.drawer {
  position: fixed;
  inset: 0 auto 0 0;
  width: 320px;
  transform: translate3d(-100%, 0, 0);
  transition: transform .25s ease-out;
  will-change: transform;
}
```

用 will-change 提前提示浏览器提升图层，动画结束后及时撤销。

```javascript
const drawer = document.querySelector('.drawer');
function toggle(open) { drawer.classList.toggle('open', open); }
drawer.addEventListener('transitionend', () => {
  drawer.style.willChange = 'auto';
```

## 注意事项

will-change 不宜长期常驻，会占用显存；大量元素同时提升图层反而更慢。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。

在跨团队协作时，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。
