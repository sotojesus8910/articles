# 退款表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:262d7a4e-4b89-4553-a875-c04a2f8f3e19 -->

## 问题场景

退款录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  amount: (v) => (/^\d+$/.test(v) ? '' : '退款必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，避免问题积累到难以收场。

从长期维护角度看，优先保证失败时能快速定位原因，以便快速定位瓶颈。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

遇到复杂链路时，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。

在压测阶段，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

针对这类偶发问题，尽量把决策依据写进变更说明，让新人上手时少走弯路。

对稳定性要求高的场景，需要评估对现有调用方的影响面，以便快速定位瓶颈。

结合团队现状，可以通过日志补充上下文信息，避免问题积累到难以收场。
