# 电表推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:cbf8d1bb-e36f-4471-8c00-c1dceec64caf -->

## 问题场景

电表状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/meter/stream', (msg) => {
  state.count += 1;
  document.querySelector('#meter-badge').textContent = state.count;
});
```

## 验证方法

手动断网再恢复，观察控制台是否在数秒内重建连接且状态不重复刷新。

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

在资源受限的环境下，建议在变更前留一份可回滚的快照，并保留回滚开关以便快速恢复。

上线初期，要把边界条件列成清单逐项确认，防止出现隐性回归。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。
