# 阈值规则字典查询加上缓存后减少重复计算

<!-- content-workspace-job:827ac473-03db-4acb-a8ac-cd3b06ac3936 -->

## 问题场景

每次渲染阈值规则详情都要重复计算同一组派生字段，调用量一上来 CPU 就被同一段逻辑吃掉。

## 实现步骤

把派生逻辑抽成只依赖入参的纯函数，加 lru_cache 并设定合理容量。

```python
from functools import lru_cache

@lru_cache(maxsize=1024)
def summary(ident, version):
    rows = fetch_rows(ident)
    return {"id": ident, "total": sum(r["threshold"] for r in rows), "v": version}
```

数据变更时主动调用 cache_clear，或把版本号作为入参的一部分。

```python
def invalidate():
    summary.cache_clear()
    return summary.cache_info().currsize
```

监控缓存命中率，命中率长期偏低说明入参过于分散，缓存没有意义。

```python
a = summary("rule-1", 85)
b = summary("rule-1", 85)
print(a == b, summary.cache_info().hits)
```

## 验证方法

连续调用同一参数两次，第二次的耗时应显著低于第一次，且返回值完全一致。

## 注意事项

lru_cache 要求入参可哈希，传列表会直接报错；缓存会延长对象生命周期，大对象要设 maxsize。

对于刚接手的同学，要明确各项资源的释放时机，并同步给相关方知会。

如果数据量继续增长，优先用工具把现状量化出来再动手，让排查路径更短。

在迁移过程中，可以通过压测确认容量水位，之后再考虑扩大适用范围。

在实际落地时，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使运维成本保持在合理区间。
