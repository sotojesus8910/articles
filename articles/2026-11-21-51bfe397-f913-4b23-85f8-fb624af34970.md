# 读懂事件表查询的 EXPLAIN ANALYZE 输出

## 问题场景

事件表的接口慢，看执行计划觉得没问题，因为看的是预估。预估行数和实际差了两个数量级，优化器据此选错了连接方式。

## 实现步骤

加 ANALYZE 拿到真实执行数据，逐节点的 actual time 是排查重点。

```sql
EXPLAIN ANALYZE SELECT * FROM events WHERE payload > 4096;
```

加 BUFFERS 看缓存命中，大量读磁盘说明缓存不够或扫描过多。

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT COUNT(*) FROM events WHERE payload > 4096;
```

对比预估与实际行数，差距大就更新统计信息或调大采样比例。

```sql
SELECT relname, seq_scan, idx_scan
FROM pg_stat_user_tables WHERE relname = 'events';
```
