# 副本模块按路由拆分后再懒加载

<!-- content-workspace-job:8b77c363-4326-447c-b522-24d1e59738d1 -->

## 问题场景

副本后台首屏加载了全部页面代码，包体积接近三兆，弱网下白屏时间很长。

## 实现步骤

路由配置里用动态 import 替代静态引入，构建工具会自动拆包。

```javascript
const routes = [
  { path: '/', component: () => import('./Home.js') },
  { path: '/replica', component: () => import('./ReplicaPage.js') },
];
```

给懒加载组件加加载态与错误兜底，避免等待期间没有任何反馈。

```javascript
async function navigate(path) {
  const hit = routes.find((r) => r.path === path) || routes[0];
  const mod = await hit.component();
  return mod.default ? mod.default() : mod.render();
}
```

## 注意事项

拆得太细会产生大量小请求，反而拖慢首屏；预加载策略要按真实路径设置，否则等于没拆。

如果数据量继续增长，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

在压测阶段，尽量把决策依据写进变更说明，让新人上手时少走弯路。

结合团队现状，可以通过压测确认容量水位，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。
