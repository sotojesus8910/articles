# 用 SSE 向支付单页面推送实时状态

<!-- content-workspace-job:6eeddc8b-e257-49bf-8928-6d77b11906a1 -->

## 问题场景

支付单的进度页面用轮询，每秒一次，几百个用户同时打开就把接口打满，大部分请求还没有新数据。

## 实现步骤

服务端保持长连接，响应头声明事件流类型并关闭缓存。

```typescript
res.writeHead(200, {
  "Content-Type": "text/event-stream",
  "Cache-Control": "no-cache",
  Connection: "keep-alive",
});
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
```

有新数据就往连接里写一条事件，格式是 data 加空行。

```typescript
const timer = setInterval(() => {
  res.write(`data: ${JSON.stringify({ t: Date.now() })}\n\n`);
}, 1000);
```

客户端断开时清理定时器，否则连接关了还在往里写，服务端句柄泄漏。

```typescript
req.on("close", () => {
  clearInterval(timer);
  res.end();
});
```

## 注意事项

SSE 只支持服务端到客户端单向通信，需要双向就用 WebSocket；中间代理可能缓冲响应，要显式关闭缓冲并调大超时。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

在实际落地时，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。

对于刚接手的同学，应定期回顾相关监控指标，以便后续复盘有据可查。

结合团队现状，可以通过日志补充上下文信息，保证每一步都可验证。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。
