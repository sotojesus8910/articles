# 传感器展示组件用自定义元素封装

## 问题场景

传感器卡片在三个页面各写一份，改样式要同步三处，很容易漏改。

## 实现步骤

继承 HTMLElement 并挂到 shadow root，样式天然隔离。

```javascript
class SensorCard extends HTMLElement {
  static get observedAttributes() { return ['title', 'value']; }
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }
}
```

声明 observedAttributes，属性变化时只更新对应节点。

```javascript
  render() {
    this.shadowRoot.innerHTML = `
      <style>.box{padding:10px;border:1px solid #ccc}</style>
      <div class="box"><b>${this.getAttribute('title') || ''}</b>
      <span>${this.getAttribute('value') || 0}</span></div>`;
  }
```

在 connectedCallback 里完成首次渲染，移除时解绑监听。

```javascript
customElements.define('sensor-card', SensorCard);
const el = document.createElement('sensor-card');
el.setAttribute('value', '512');
document.body.appendChild(el);
```

## 注意事项

自定义元素名必须含连字符；shadow DOM 内的样式不会外泄，但外部也无法用普通选择器覆盖，需用 CSS 变量做定制入口。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，避免问题积累到难以收场。

从成本角度看，应当限定作用范围避免影响其他业务，使整体改动风险可控。

如果数据量继续增长，优先用工具把现状量化出来再动手，防止出现隐性回归。

对稳定性要求高的场景，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，确认指标平稳后再逐步放开。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

从排障效率看，要明确各项资源的释放时机，确保线上行为始终可控。

遇到复杂链路时，优先保证失败时能快速定位原因，以便快速定位瓶颈。

在跨团队协作时，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。
