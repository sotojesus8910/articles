# 请假单表单在提交前做集中校验并聚焦首个错误

<!-- content-workspace-job:558f8d08-9fd2-4149-93f6-7d513096a5e1 -->

## 问题场景

请假单录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  days: (v) => (/^\d+$/.test(v) ? '' : '请假单必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，避免问题积累到难以收场。

对于刚接手的同学，要明确各项资源的释放时机，以便快速定位瓶颈。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

针对这类偶发问题，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。
